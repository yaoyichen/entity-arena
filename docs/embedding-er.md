# Embedding 模型在实体归能中的用法与微调为何有效

> 本文回答两个问题：① 一条"记录"是怎么变成向量、向量又是怎么变成"同一实体/不同实体"判定的；
> ② 在 Febrl3 基准上，基座 embedding 模型本来已经不差（recall@5 ≈ 0.97+），后训练到底改了什么，
> 使指标推到 1.0、案例村 323 对真值零误连零漏连。
> 所有数字均为本仓库可复算的实测值（`data/open_benchmark.json`、`data/open_cases.json`）。

## 1. ER 问题的重述：从"比较字符串"到"比较向量"

实体归能（Entity Resolution）问的是：**两条记录是否指向同一个现实实体**。

传统做法是规则打分器：逐字段算编辑距离、加权求和、过阈值。它的问题在"权重"是死的——
"姓名完全不同"在一条记录对里是致命证据（不同人），在另一条里却无所谓（同一个人，
 surname 被 OCR 打烂了，但 SSN 精确一致）。字面相似度无法区分这两种情形，因为它的
"相似"没有实体概念。

Embedding 模型的用法是把判定搬进几何空间：

```
记录 ──serialize──► 文本 ──encoder──► 向量 v ∈ R^768
判定 = ( cos(v_a, v_b) ≥ θ )        # 过线 → 断言"同一实体"
```

关键在于：**"同一实体"这个定义必须已经被烙进向量空间的几何里**——同实体的记录对聚成团，
高仿的异实体对被推开。基座模型的几何不是这样组织的（见 §3），这正是后训练做的事。

## 2. 本项目的完整流水线

```
Febrl3 CSV (5000 记录 / 2000 实体, recordlinkage 生成, 含 OCR 错/音译错/字段缺失)
   │  scripts/make_open_dataset.py
   ▼
BEIR 检索格式训练包（queries=corpus=全部记录; qrels=同实体对 score 1;
                     硬负例=同姓/同 suburb+postcode/同生日的异实体记录）
   │  inf-retriever 平台, use_hard_negatives=true
   ▼
微调模型（如 febrl3-er-gemma, base=embeddinggemma-2）
   │  平台评测(pytrec_eval, 固定 test split)          ──► 检索式指标 (§2.2)
   │  部署服务 /v1/embeddings 取真实向量               ──► 成对式判定 (§2.3)
   ▼
cos ≥ θ 断言链 ──并查集──► 组件 = "模型声称的实体" ──对真值──► 纯度/误连/漏连
```

### 2.1 记录 → 嵌入文本（`src/entity_arena/febrl.py: serialize`）

```text
name: spencer green | DOB: 1942-03-13 | address: 24 yarra street katalina forrest
| locality: taret 3829 act | SSN: 8155837
```

规则只有两条，都值得注意：

- **只写存在的字段，不补占位符**。属性缺失是 ER 的常态而非异常——一条记录只有姓名和
  SSN、另一条有完整地址，它们的嵌入文本长度和内容天然不同，模型必须学会"缺失 ≠ 冲突"。
- **字段名显式写进文本**（`name:` / `DOB:` / `SSN:`），给模型一个稳定的结构锚点，
  让"SSN 精确一致"和"地址里恰好出现同一个数字"在表征里可区分。

### 2.2 用法之一：检索式（blocking / 候选生成）

每条记录既当 query 又当 document（同池自检索），检索 top-k 相似记录。
这是平台评测的口径（recall@k、NDCG@k），也是生产系统的第一段：n 条记录两两比较是
O(n²)，用 embedding 建 ANN 索引把每个实体候选压到 top-k，才是可扩展的姿势。

### 2.3 用法之二：成对式（判定）

两条记录 → 余弦 → 与 θ 比较 → 断言连接与否。断言链经并查集成"组件"，组件对着
Febrl3 真值（`rec_id` 里的实体号）算纯度。θ 不是拍的，是**在案例村上扫描 link-F1
最大化**选出的（平局取精度高、再取 θ 大者，规则写在 `open_cases.json` 的
provenance 里）。现场演示可用 `scripts/live_pair_score.py` 实时打分任意两条记录。

## 3. 为什么后训练起了效果

### 3.1 核心机制：把"语义相关"改写成"身份等价"

基座 embedding 模型的预训练目标是**语义/主题相似**——"how do I renew a passport" 和
"passport renewal process" 应该相近。这个几何搬到 ER 上，恰好在最难的地方出错：

| 记录对 | 语义/字面相似度 | ER 真值 | 通用几何的判断 |
|---|---|---|---|
| 同姓、同名差一字母、同 suburb 的两条记录 | **很高** | 不同人 | 高分 → 误连 |
| 姓名被 OCR 打烂、生日缺失、SSN 精确一致的两条记录 | **中等偏低** | 同一人 | 中低分 → 漏连 |

微调做的事情就一件：**重塑向量空间里这两个区域附近的局部几何**，让"身份等价"取代
"语义相似"成为组织原则。这是目标函数层面的重定义，不是"见更多数据"那么含糊。

### 3.2 硬负例把决策边界画在错误高发区

训练包里每个查询配 ≤5 个硬负例（共 10998 个），挖掘规则是**同姓 / 同
(suburb,postcode) / 同生日的异实体记录**——这三种恰好是字面相似度和语义相似度都会
打高分的"高仿对"。对比损失（in-batch negatives + 标注硬负例）一边把同实体对拉近、
一边把这些高仿对推开，**边界正好落在基模型分不开的那片区域**。

这不是偶然的设计：硬负例的挖掘规则就是"哪里容易错就练哪里"。如果只用随机负例，
模型只会把"风马牛不相及"的对推开——那本来就不难。

### 3.3 分布适配：字段化模板文本 + 字符级噪声

基模的预训练语料以自然语言为主；ER 的嵌入文本是 `字段名: 值 | 字段名: 值` 的模板
结构，且噪声是**字符级**的（`spencxr`、`srteet`、邮编 3829↔3820）而非词义级的。
微调让 encoder 的表征适应这种分布——尤其学会对错字保持平滑（地址错字无害）、对
关键字段的数字差异保持尖锐（SSN 差一位就不同人）。

### 3.4 校准效应：分数两极化 → 单一 θ 够用

判定要用单一阈值 θ，前提是分数分布围绕"身份"两极化：真对集中高区间、假对压低区间，
中间留缝。看实测两张卡（`build_open_cases.py` 按确定性极值规则挑出，对叙事盲）：

- **R1「错字风暴仍连对」**：`spencer green` vs `spencxr royans`——姓名整段冲突
  （编辑相似度 0.57）、生日一侧缺失，但 SSN 精确一致、地址是典型 OCR 错字。微调模型
  给 **0.9456 ≥ θ=0.9208**，断言连接，真值确实是同一实体。字面加权打分器在这里会
  被姓名冲突拖死。
- **R2「长得最像仍拒连」**：案例村里分数最高的被拒异实体对（**0.9106 < θ**）。
  值得注意的是它绝对分并不低——微调后的余弦整体压缩在高区间，**判别力在带宽内部的
  相对结构里，而不在绝对值**；θ 是在这个分布上按 F1 扫出来的，所以能切在缝上。

这两张卡就是微调边界的可视化：R1 证明模型学会了"哪些差异可容忍"，R2 证明学会了
"哪些相似不可信"。

### 3.5 实测证据

**平台评测（检索式，400 测试实体 / 2598 真值对，pytrec_eval 固定 split）：**

| 基座模型 | recall@5 前→后 | NDCG@10 前→后 | win/tie/loss |
|---|---|---|---|
| inf-retriever-v1-1.5b-pro | 0.978 → 0.997 | 0.986 → 0.998 | 63 / 780 / 7 |
| nemotron-3.5-embed-1b-bf16 | 0.999 → 1.000 | 0.999 → 1.000 | 6 / 844 / 0 |
| embeddinggemma-2 | 0.972 → **1.000** | 0.980 → **1.000** | 80 / 770 / **0** |

要诚实地说：**基模本来已经很好**（recall@5 ≈ 0.97+），因为 Febrl3 里大多数异实体对
字面上就差得远。微调啃的是尾部难例——gemma 每 1000 个查询少漏 28 个真对，且
loss=0 说明改善是逐查询的、没有拆东墙补西墙。

**案例村（成对式，228 记录 / 78 实体 / 323 真值对，febrl3-er-gemma 真实向量）：**

| | 微调模型（真实余弦） | 字面相似度代理基线 |
|---|---|---|
| θ | 0.9208 | 0.56 |
| precision / recall | **1.000 / 1.000** | 0.971 / 0.947 |
| 误连 / 漏连 | **0 / 0** | 9 / 17 |
| 组件纯度 | 78/78 全纯 | 72/76 |

代理基线（字段 Levenshtein 加权，权重与口径公开在 provenance）就是"没有学过身份
概念"的打分器：9 条误连全是高仿对，17 条漏连全是错字风暴——正好对应 §3.1 的两类
错误。微调模型在同一村子上零误连零漏连。

## 4. 诚实边界

- **θ 的选择**：在案例村上按 link-F1 最大化选出，规则随数据公开（`open_cases.json`
  provenance），不是跨数据集的普适常数。
- **"微调前"网络视图态是代理**：平台只能部署已训练模型，基模逐条分数不可得；网络
  视图的"原始→基线"态用字面相似度代理呈现。真实基线的**检索**指标（上表）在记分牌
  开源基准轨，两者口径各自标注。
- **自检索口径**：查询与文档同池，top-1 常是记录自身，故 recall@1 ≈ 0.44 是两模型
  同口径的均匀代价，绝对值按"有效 k-1"解读。
- **结论范围**：Febrl3 是 recordlinkage 生成器的开源基准（含真实的错误模型：OCR 错、
  音译错、字段缺失/冲突），不是生产脏数据；以上结论限定于该基准，不外推。
- **余弦绝对值不可跨模型比较**（见 §3.4 R2 的讨论），θ 必须在各自模型的分数分布上重扫。
