## 2. 我们怎么思考的

### 2.1 约束盘点（做演示前的实况）

| 约束 | 应对 |
|---|---|
| 没有客户真实数据 | 合成数据（剧本人物保叙事，填充人物保统计面）+ Febrl3 开源基准（含 OCR 错/音译错/缺失/冲突的真实噪声模型） |
| 演示第一版没跑真模型 | 第一版用**代理评分**保叙事层（口径写明，ADR 0002）；**现已补齐真模型层**：Febrl3 → 平台微调 ×3 基座 → 评测（报告入库）→ 部署服务 → live 现场打分 |
| 会议时间紧、现场不可控 | 单文件离线页零外链；live 全部有入库兜底（服务挂了照讲） |
| 客户方有数据分析负责人 | 指标口径前置设计，四个指标各答一个问题；实测轨 θ 选择/选村规则全部写死在 provenance |

### 2.2 三个核心决策

**D1：不空谈，做"可操作的数据演示"。**
架构图谁都会画。客户邮件通篇是 "The System shall…"——验收式语言，
回应它的唯一方式是让他**点得到**：点一条查询、点一个节点、看一次分数变化。

**D2：核心冲突必须是"同一个世界、两个模型"。**
单模型演示没有参照系，客户无法判断"好不好"。我们展示**同一批合成记录上
baseline（开箱 embedding 代理）vs 微调后**的并排对决——差距出现在哪、
为什么、代价是什么（误连会凭空捏造一个人）。

**D3：诚实边界反而更强。**
- 页脚明写 SYNTHETIC DATA；分数口径写进 Scoreboard 脚注；
- **故意保留一处失手**（Q6 曾用名：微调也不过线）——主动展示天花板，
  恰好说明哪些能力必须靠真模型/真数据去补（见 D4 与实测轨）；
- 对方带 Data Analytics lead，与其被问穿，不如先说清。
  信任建立的顺序：先承认边界，再展示差距。

**D4（后续演进）：真模型实证层。**
第一版的"两个模型"是公式代理，说服力有天花板。现在同一叙事加了实测层：
Febrl3（5000 记录 / 2000 实体，开源基准）→ 构造训练包（正例=同实体对，
硬负例=同姓/同址/同生日的高仿异实体对）→ inf-retriever 平台微调三个基座 →
固定 test split 评测 → 部署服务现场打分。演示页因此是**两层证据**：
合成轨讲清机制（ER 难在哪、微调学什么），实测轨给出真数字
（三个基座 recall@5 从 0.97+ 全部推到 0.997–1.000，gemma 达 1.000）。

### 2.3 演示动线为什么是"故事 → 结构 → 数字"

1. **Arena（故事）**：6 个剧本查询是人能共情的个案（一张光秃秃的酒店入住单、
   两个张伟、一对双胞胎）——先建立"这问题真的难"；
2. **Network（结构）**：47 条记录从 5 个孤岛归并成 19 个实体——展示 ER 的
   产出形态（consolidated view，对应 U3/U6）；
3. **Explain（机制）**：逐字段拆一对记录为什么连/不连——展示可解释性，
   打消"黑盒"疑虑；
4. **Scoreboard（数字）**：最后才上指标——此时每个指标客户都能对上
   刚才看过的案例，数字有根。

实测轨沿同一条动线嵌入：三态网络进"结构"（毛线球→基线翻车→微调拆解），
R1/R2 实测卡 + live 进"机制"，开源基准记分牌进"数字"——叙事弧线不变，
证据从代理升级为实测。

## 3. 怎么做的（实现一瞥，客户问起时用）

```
合成轨（叙事层，代理评分）：
synth.py ──► simulate.py ──► layout.py ──► build_demo.py ──► demo.html（单文件）
 合成世界      双模型评分+指标   网络两套坐标      打包渲染          零外链·断网可开
（seed 钉死）  （代理评分）      （预计算）        （self-check）

实测轨（真模型层）：
make_open_dataset.py ──► inf-retriever 平台 ──► update_open_benchmark.py ──► demo.html 同页第二轨
 Febrl3→训练包           微调×3基座+评测+部署    + build_open_cases.py          + live_pair_score.py
 （qrels+硬负例10998个）  （报告入库可溯源）      记分牌/案例村三态/实测卡        现场实时打分
```

- **合成轨数据**：19 实体 / 47 记录 / 5 数据源（户籍·出入境·银行·运营商·酒店）。
  6 组剧本人物手工设计（同名异人、双胞胎、粤拼音译、曾用名、2月30日生日），
  12 组填充人物 seed 生成；一切随机钉死 seed=42，逐字节可重建。
- **合成轨代理评分**：baseline = 字面相似度加权（跨文字名字≈全盲，这是开箱模型
  的真实弱点）；微调 = 字面信号 + "学到的"等价（0.30·base + 0.70·oracle，
  有佐证才触发跨文字推理）。仅 4 对关键案例分数剧本钉死，其余公式涌现。
- **实测轨**：Febrl3 实体级 80/20 切分防泄漏（案例村 ⊂ test 实体，选村对分数盲）；
  训练对 10478、硬负例 10998；三基座（inf-retriever-v1-1.5b-pro /
  nemotron-3.5-embed-1b / embeddinggemma-2）平台微调；指标口径 pytrec_eval 固定
  test split。成对判定 θ 在案例村（228 记录/78 实体/323 真值对）上按 link-F1
  最大化扫出（θ=0.9208），规则写进 provenance。
- **合成轨指标口径**：每条记录作查询、检索其余取 top-5、断言=分数 ≥0.55。
  recall@5（找得回吗）/ link_recall（敢连吗）/ link_precision（连得对吗）/
  false_link_rate（影子人误连率，仅相似实体场景）——四个指标各答一个问题。
- **工程**：Python 纯标准库零依赖；77 项测试（剧本数值逐对锁定、确定性、
  零外链契约、实测轨断言链复算）；详见 `docs/adr/0001`（SVG 预计算布局）、
  `0002`（代理评分诚实性）、`docs/embedding-er.md`（Embedding×ER 技术说明）。

## 5. Q&A 备忘（对方可能问的 10 个问题）

**Q：数据是真的吗？**
A：两层。合成轨：全部合成，种子固定，一条命令逐字节重建，无任何真实个人信息。
实测轨：Febrl3 开源基准（recordlinkage 生成器，公开数据集）——不是我们的数据，
也不是挑过的；模型分数、指标全部真实可复算。两层都没有隐私合规负担，
可以直接公开演示。

**Q：那分数是哪来的？模型是什么？**
A：分两层说清。合成轨：代理评分——基线=字面相似度加权（跨文字近盲是它的
真实弱点），微调=字面信号+模拟学到的等价，只有 4 对关键案例分数钉死，
其余公式涌现，用来讲机制。实测轨 + live：真模型 febrl3-er-gemma
（基座 embeddinggemma-2），平台微调、部署服务 /v1/embeddings 的真实输出，
评测报告入库可查（NDCG@10=1.000）。两层口径页内各自标注，不混。

**Q：换成我们的数据要多久？**
A：两条路都通。演示页：字段映射到记录 schema，跑分脚本输出 results/metrics
两个 JSON，页面零改动；真模型链路：造训练包 → 平台微调 → 评测 → 部署，
开源轨三条命令重跑全链路。数据侧如果需要脱敏/抽样，用你们习惯的通道。

**Q：非结构化数据（文书、邮件）支持吗？**（邮件 U3 提到 structured+unstructured）
A：这次演示覆盖结构化属性。非结构化的路径是：抽取（把文书里的姓名/证件/日期
抽成结构化字段）+ 同一套匹配底座。抽取和匹配共用我们的检索/微调能力，
是同一管线的两个阶段。

**Q：和 RAG / INF 套件什么关系？**
A：ER 本质是"以记录检索记录"的极高标准——top-5 里必须精确命中同实体。
这与 RAG 用的是同一个检索模型微调底座；这里展示的冲突容忍、跨文字等价学习，
就是微调能力在不同任务上的迁移。

**Q：为什么阈值是 0.55？**
A：演示口径的设定值：低于它不构成断言（只算候选）。实际部署中阈值是
业务旋钮——高阈值少误连、低阈值高召回，Scoreboard 的口径会跟着重算。

**Q：规模能到多大？实时吗？**
A：演示页是 47+228 条记录、离线单文件；评测在全量 5000 条 Febrl3 上做
（检索式 recall@5=1.000）。真实规模取决于检索底座（百万级向量检索是成熟
技术，ER 用它做候选召回，再逐对过 θ 判定）；实时/增量接入是工程问题，
不是方法问题——这一点放进落地路线。

**Q：微调具体怎么做？**
A：这次演示就是这么做的：Febrl3 造训练包——正例=同实体记录对（10478 对），
硬负例=同姓/同址/同生日的**高仿异实体对**（10998 个，专挑字面方法会看走眼的），
实体级 80/20 切分防泄漏 → 平台对比学习微调 → 固定 test split 评测 → 部署。
换成您的数据是同一条管线，第一步是字段映射和造对。

**Q：为什么 baseline 不能现场打分？**
A：平台 `deploy_model` 仅支持已训练模型，基模无法逐条部署。基线的真实检索
指标在记分牌（同集离线评测，公平）；网络视图里的"基线"态是字面相似度代理，
页内三处标注口径。

**Q：live 分数每次会一样吗？**
A：GPU 推理逐批有 <0.005 的浮点抖动（入库 0.946 vs 现场 0.945），判定不变——
演示对的边界余量都按距 θ ≥0.01 选过。这个抖动恰好证明是真服务不是录像。
