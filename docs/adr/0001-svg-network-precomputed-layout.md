# ADR 0001：网络视图用预计算坐标 + 手写 SVG，不引 sigma.js / d3

日期：2026-11-08
状态：已实施

## 背景

Network 视图要展示"归并前（按来源孤岛）→ 归并后（按实体聚合成 halo）"的形变动画，
候选方案有三：

1. sigma.js / d3-force 等图可视化库；
2. 服务端布局 + 前端插值；
3. 纯手写 SVG（坐标全部 Python 预计算）。

约束（继承 retrieval-forge 的演示页硬规矩）：**单文件、零外链、断网双击能开、
同输入同输出**。节点规模：19 实体 / 47 记录，≤60 节点。

## 决策

选 2+3 的合并：**Python 算好 before/after 两套坐标打进 JSON，前端只做插值（morph）**。
浏览器里没有任何布局计算。

- before：5 个来源锚点（椭圆分布）+ 高斯抖动 + 60 轮点对松弛；
- after：实体级 Fruchterman-Reingold（纯标准库实现）→ 分位数归一化（2%–98%）
  → **光环防撞**（`_separate_halos`：实体中心两两推开 r_i+r_j+14）→ 成员绕中心排环。

## 踩过的坑（都有测试兜底）

1. **力导向不做硬 clamp**——clamp 会把节点钉在边界排成点带
   （retrieval-forge ADR 0005 的元凶，这里直接继承结论：归一化在收敛后做）。
2. `y1 - y1` 手误让 y 轴分位归一化静默失效——同类表达式要 review；
   现在有 `test_nodes_in_canvas` / `test_entity_halo_no_overlap` 兜底。
3. 前端补画 before 边时漏了给 `<line>` 设坐标，边全部塌缩在原点不可见——
   SVG 元素不设坐标不报错，必须截图验证。
4. 光环压叠：双胞胎/同名实体的 halo 一旦重叠，"这是两个人"的叙事就垮了；
   防撞是**叙事需求**不是美观需求，所以 `_separate_halos` 放在构建管线里而非可选。

## 后果

- 正面：断网可开、完全确定性（同 seed 两次构建逐字节一致，有测试）、
  动画只是插值不会抖、零第三方依赖。
- 负面：节点数上百后手写 SVG 会到极限；届时再评估 canvas 渲染或库，
  但"坐标预计算、前端只插值"的架构不用变。
